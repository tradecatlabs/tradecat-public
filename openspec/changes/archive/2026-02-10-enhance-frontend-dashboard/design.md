## 上下文

TradeCat 前端当前使用静态 HTML + JavaScript 实现，通过 HTTP 轮询方式访问 API 服务。API 服务已提供完整的端点：
- `/api/indicator/snapshot` - 单币完整快照（38 个指标）
- `/api/indicator/list` - 可用指标列表
- `/api/futures/ohlc/history` - K 线历史数据
- `/api/futures/base-data` - 基础数据
- `/api/signal/cooldown` - 信号冷却状态

SQLite 数据库已包含 38 张指标表，数据实时更新。当前前端仅展示 12 个主要指标，缺少时间戳、期货历史图表、完整指标列表等关键功能。

## 目标 / 非目标

**目标：**
- 数据时间戳显示，让用户知道数据的实时性
- 展示全部 38 个技术指标（按类别组织）
- 持仓量、资金费率的历史趋势图表
- 支持近一个月（30天）历史数据查看
- 保持单页面应用，无需后端改动

**非目标：**
- 不实现 WebSocket 实时推送（使用轮询）
- 不添加用户系统或认证
- 不实现交易执行功能
- 不修改后端 API

## 决策

### 1. 数据获取策略
**选择**: 利用现有 `/api/indicator/snapshot` 端点一次性获取所有指标
**理由**: 
- 减少 API 调用次数
- 该端点已优化，返回完整数据结构
- 比逐个调用 `/api/indicator/data` 更高效

**替代方案**: 逐个指标调用 `/api/indicator/data`
- 缺点：38 个指标 = 38 次 API 调用，性能差

### 2. 历史数据展示
**选择**: 默认加载近 30 天数据，前端提供时间范围选择器
**理由**:
- 满足"近一个月"需求
- API 支持 limit 参数控制数据量
- 使用 lightweight-charts 的 timeScale 进行缩放

**替代方案**: 后端添加日期范围过滤
- 缺点：需要修改后端，超出当前范围

### 3. 期货图表实现
**选择**: 使用 Chart.js 绘制持仓量、资金费率趋势图
**理由**:
- 轻量级，易于集成
- 支持时间轴、多数据集
- 与现有 lightweight-charts 不冲突（K线用 lightweight-charts，期货用 Chart.js）

**替代方案**: 全部使用 lightweight-charts
- 缺点：lightweight-charts 更适合金融 K线，普通折线图 Chart.js 更灵活

### 4. 实时更新机制
**选择**: 保留现有 30 秒轮询，添加手动刷新按钮
**理由**:
- 实现简单，无需 WebSocket
- 交易数据不需要毫秒级实时
- 30 秒间隔平衡实时性和服务器负载

**替代方案**: WebSocket 实时推送
- 缺点：需要后端支持，增加复杂度

### 5. 指标组织方式
**选择**: 按类别分组展示（基础/期货/高级），支持折叠展开
**理由**:
- 38 个指标一次展示过于拥挤
- 用户可按关注点查看
- 符合 API 返回的 panel 结构

## 风险 / 权衡

**[性能] 38 个指标一次性加载可能导致页面卡顿**
→ 缓解措施：
- 使用虚拟滚动或分页
- 默认只展开基础指标，其他折叠
- 指标卡片延迟渲染

**[兼容性] 不同浏览器的 Canvas 性能差异**
→ 缓解措施：
- 使用成熟的图表库（lightweight-charts, Chart.js）
- 提供降级方案（表格视图）

**[数据一致性] SQLite 和 PostgreSQL 数据可能不同步**
→ 缓解措施：
- 显示数据来源时间戳
- 明确标注数据更新时间

**[API 限制] 部分 futures API 可能返回 500 错误（如持仓量）**
→ 缓解措施：
- 前端优雅处理错误，显示占位符
- 记录错误日志，不影响其他功能

## 技术栈

- **K线图表**: lightweight-charts (已有)
- **期货图表**: Chart.js 4.x
- **HTTP 客户端**: 原生 fetch API
- **样式**: 原生 CSS (保持现有深色主题)
- **图标**: Emoji (保持简单)
